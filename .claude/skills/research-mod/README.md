# research-mod

This folder is both the `research-mod` skill (`SKILL.md`) and a Claude Code mod of the same name,
for the `opendatamcp` workspace. The mod shows which open-data research topic (`data/<topic>/`)
the session is working on. It lists that topic's datasets, fields and provenance in a side pane,
read from each dataset's `source.json`.

It was split out of `opendata-research`. That skill fetches and records the data, and this
mod displays it.

## Loading

Claude Code loads the skill and the mod from `.claude/skills/research-mod/` automatically when
`claude` starts in the `opendatamcp` folder. No `--plugin-dir` is needed; passing one as
well loads it twice. Saving a file in the mod reloads it.

## What it does

- **Status line:** `Researching: <topic>`. The topic comes from the first `data/<topic>/`
  path a tool call names in `file_path`, `path`, `command` or `notebook_path`. The trailing
  slash is required: `data/electricity-prices/` matches, `data/electricity-prices` does not.
  Loose files directly in `data/` and `data/` folders inside other projects (such as
  `data-gov-ie-mcp/data/`) are ignored.
- **`/datasets`:** opens the **Datasets** side pane. It also opens by itself when the topic
  changes. For each dataset folder under the topic (except `dashboard-*`) it shows the title,
  source, latest period, upstream update date, latest snapshot (file, rows, fetch date,
  snapshot count), publisher, units, notes, fields with their roles, measures, and a link to
  the landing page.
- **Used datasets:** folders a tool call named this session are marked ● and listed first,
  open. The others start closed. Click a dataset to open or close it. Press `c` to collapse
  all and `e` to expand all.
- **Live updates:** `source.json` files are read again after every tool call under the topic,
  so a new snapshot or a `describe_fields.py` run shows straight away.

## Depends on

The pane depends on the `source.json` layout written by the `opendata-research` skill and its
`describe_fields.py`:

- `snapshots[]`: `file`, `fetched_at`, `upstream_updated`, `latest_period`, `rows`
- `fields[]`: `name`, `role`, `categories`, `min`/`max`, `blanks`
- `measures[]`: `statistic`, `unit`, `min`/`max`

If you change one side, change the other to match.
